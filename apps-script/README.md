# 更新會員手機（V2，保留所有原會員資料）

## 已安裝 V1 的使用者

1. 將此資料夾 `MemberPhoneUpdate.gs` 的完整內容，取代 Apps Script 中同名檔案的全部內容。不要覆蓋 Code.gs，也不要另建第二份同名函式。
2. Code.gs 既有路由保持不變：
   ```javascript
   case 'updateMemberPhone': result = updateMemberPhone(data); break;
   ```
3. 儲存，進入「部署 → 管理部署作業 → config.js 對應的部署 → 鉛筆 → 版本選『建立新版本』→ 部署」。只修改說明或使用舊版本不會套用新程式。
4. 重新整理 GitHub 會員網頁，用舊手機查詢會員，再填新手機，按「儲存新手機」。

## 行為

- 原會員只改電話。會員編號、姓名、消費設定、卡放店內、備註、來店次數、日期及其他欄位全部保留，不加總次數、不混入新號碼資料。
- 若新號碼沒有 CRM 資料，直接更新電話。
- 若新號碼已有一筆 CRM，先顯示新舊客戶姓名與電話，要求確認同一人；取消不寫入。
- 確認後先複製完整 CRM 工作表為 `CRM_Backup_時間_識別碼`。備份成功才更改原會員電話、清空重複 CRM 列。該重複列的全部資料留在備份，不匯入原會員。清空列而不刪除列，避免其他客戶列號位移。
- 新號碼已有不同會員編號、多筆相同電話、資料在確認期間變動，或待合併列含公式時，停止操作。
- 寫入失敗會嘗試還原兩筆原 CRM 資料；若還原不完整，明確提示停止重試及備份名稱。Apps Script 試算表操作不是跨呼叫交易，執行遭強制中止等情況仍需依備份核對。
- RawData、iPad 訂單與歸檔完全不改，歷史電話保持原樣。依電話查詢的歷史記錄不會自動轉到新號碼。
- 成功後清電話快取並同步 Membership；衍生列表同步失敗會提示手動重新整理，不誤報 CRM 沒有更新。
- 與 processCustomerVisit 共用 ScriptLock。既有未上鎖管理函式和手動試算表編輯仍應避免與換號同時執行；同頁新增、刪除、換號互相鎖定。

## 驗證

執行 `node tests/member-phone-update.test.cjs`。模擬測試涵蓋一般換號、逐欄保留、同號／錯號／重複／不同卡號阻擋、預覽無寫入、確認後去重、過期確認、重試不重複處理、備份失敗、写入失敗還原、取消合併、重複送出、網路錯誤與部分同步失敗。

未以真實會員執行寫入。部署後需由操作者核對確認畫面並執行實際換號。
